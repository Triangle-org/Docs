# Компоненты

Компоненты разделены на Composer-пакеты, но текущие пакеты Triangle обычно требуют `triangle/engine` и не все имеют standalone API вне его. Смотрите конкретный `composer.json` и [матрицу совместимости](/compatibility) перед выбором.

| Пакет | Назначение | Основная интеграция |
| --- | --- | --- |
| [`triangle/console`](/components/console) | команды приложения | Localzet Console и Engine; PHP `^8.2` |
| [`triangle/router`](/components/router) | сбор и диспетчеризация маршрутов | Engine; HTTP и WS движки |
| [`triangle/middleware`](/components/middleware) | middleware для приложения и маршрута | Engine и Router |
| [`triangle/database`](/components/database) | доступ к БД через Illuminate Database | Illuminate 11; PHP `^8.2` |
| [`triangle/view`](/components/view) | рендеринг представлений | Engine; Twig/Blade/Think templates — optional adapters |
| [`triangle/session`](/components/session) | HTTP-сессии | Engine; MongoDB handler предлагается отдельно |
| [`triangle/events`](/components/events) | события Triangle и listeners | Engine |
| [`triangle/cron`](/components/cron) | расписание фоновых задач | Localzet Cron и Triangle Events |

## Подключение

Варианты приложения Web/WS уже включают нужные им пакеты. Для ручной сборки используйте точные Composer constraints из конкретного компонента и выбранного движка; пакеты `triangle/engine-http` и `triangle/engine-ws` объявляют mutual conflict и относятся к разным application tracks.

Наличие отдельного репозитория означает независимое версионирование, но ещё не гарантирует заменяемость реализации или работу вне Triangle. Для самостоятельного использования проверьте импортируемые namespace и требования к Engine в manifest.
