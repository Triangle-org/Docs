# Ошибки и обработка исключений

Triangle работает как долгоживущий PHP-процесс. Ошибка одного запроса не должна оставлять загрязнённый контекст для следующего: используйте `try/finally` для собственной очистки ресурсов и не храните данные запроса в глобальном изменяемом состоянии.

## Где настраивается обработка

Общие настройки приложения и обработчик исключений задаются в `config/exception.php`. HTTP и WS движки имеют собственный lifecycle и передают ошибки в настроенный Triangle exception handler. Точный формат ответа зависит от текущего движка и конфигурации приложения.

## Практика

- Возвращайте клиенту безопасное сообщение, а подробности пишите в серверный лог.
- Не помещайте токены, пароли, session IDs и тела запросов с персональными данными в логи.
- Для ожидаемых ошибок приложения используйте исключения из доменного слоя; не превращайте все ошибки в HTTP 200.
- Для WS-соединений обрабатывайте завершение соединения и освобождайте связанные ресурсы.
- Проверяйте `config/exception.php` и выбранный `Engine-HTTP` или `Engine-WS` handler при изменении поведения ошибок.

Исходные конфиги находятся в репозиториях шаблонов; примеры сборок и границы движков описаны в [архитектуре](/architecture).
